## 3. Ключевое свойство: сайт не меняется, пока не изменили осознанно

То же правило, что у слотов картинок. `mg_list('...')` возвращает пустой массив, если
список не опубликован, и шаблон использует свой прежний массив.

Это значит: код можно выкатывать до того, как что-либо заполнено — страницы байт в байт
те же. Проверено тестами на `/`, `/arhitektuur-ja-valisdisain`, `/arendajast`,
`/sisedisain`, `/kkk`.

Отдельно проверено, что публикация **не роняет производительность**: карточки главной
после публикации по-прежнему отдают `Cam001.0000-1200w.webp`, а не полноразмерный JPEG
(для этого добавлен `mg_img_path()`).

## 4. FAQ и структурированные данные — один источник

В плане это было отмечено как важное: видимый FAQ и разметка для Google жили отдельно и
уже расходились (пункт 12 в фазе 35.1).

- `/kkk` — видимый список и блок `FAQPage` в JSON-LD строятся из одного массива `$groups`.
  Опубликованный список `kkk.faq` заменяет оба сразу. Тест проверяет, что вопрос
  встречается в HTML **ровно дважды** — в списке и в разметке.
- `/arhitektuur-ja-valisdisain` — `mg_faq()` отдаёт вопросы, а микроразметка
  `schema.org/FAQPage` навешана на тот же цикл. Разойтись физически нечему.
- Вопрос без ответа на страницу не попадает — недописанная строка не станет пустым
  блоком в выдаче Google.

Семь рубрик KKK сохранены: вопрос несёт свою рубрику, поэтому клиент может перенести
вопрос из одной рубрики в другую, не трогая вёрстку. Якорные ссылки рубрик работают.

## 5. Что умеет экран

- добавить / удалить строку;
- **перетащить** строку мышью за ручку — порядок берётся из порядка строк на экране,
  поэтому отдельной кнопки «сохранить порядок» нет и рассинхронизироваться нечему;
- три языка: эстонский обязателен, русский и английский можно оставить пустыми — тогда
  показывается эстонский (решение 4);
- «Näita lehel» — скрыть строку, не удаляя;
- картинка выбирается из медиатеки, а не вводится путём: заменили файл один раз —
  поменялось везде, где он используется.

Пустая строка, оставленная после нажатия «+ Lisa rida», не сохраняется — не превращается
в дыру на сайте.

## 6. Найдено и исправлено по ходу

**Публикация «только картинки» или «только списка» отклонялась.** Контрольная сумма
публикации считалась по снимку, куда не входили ни привязки картинок (Модуль B), ни
списки. Изменение только их выглядело как «данные не отличаются от текущей версии», и
опубликовать это было невозможно. Снимок дополнен; откат теперь тоже восстанавливает
картинки и списки, а не только тексты и цены. Два теста закрывают оба случая.

**Короткая форма `@php(...)` ломала страницы.** Этот Laravel её не поддерживает: она
компилируется в незакрытый `<?php(`, и остаток шаблона становится PHP-кодом — страница
падает на `@endif` далеко ниже. Так легли четыре шапки подстраниц. Исправлено, добавлен
тест, который сканирует все шаблоны и не даст повторить.

**Шапки подстраниц были зарегистрированы с неверными файлами.** В реестре слотов стояли
`Cam001`, `Cam014` и pptx-картинка, а страницы отдавали `Cam004`, `Cam005` и
`Interior 1.jpg`. Незакреплённый слот молча подменил бы фотографии. Дефолты приведены к
факту, добавлен тест, что файл каждого слота существует в репозитории.

**`Interior 1.jpg` — пробел в имени файла.** Реестр хранит реальное имя (чтобы проверка
существования работала), а `mg_slot()` кодирует пробел в URL.

## 7. Развёртывание

```bash
git pull
php artisan migrate               # две таблицы: magnoolia_lists, magnoolia_list_items
php artisan magnoolia:seed-lists  # импорт текущего содержимого сайта в редактор
php artisan magnoolia:seed-campaign   # см. ниже — обязательно
php artisan magnoolia:seed-gallery --dedupe   # если галерея сидилась старой версией команды
```

> **`seed-campaign` обязателен.** Фаза 35.1 перевела красный баннер «Eripakkumine…»
> на экран Campaign. На проде этот экран никогда не заполняли, поэтому после выката
> 35.1 баннер исчез со всех страниц — публикация даже не требовалась, старый снимок
> просто не содержит ключа `campaign`. Команда возвращает ту формулировку, которая
> была на сайте, во всех трёх языках. После неё нужен **Publish Website Changes**.
> Начиная с этой фазы Validate предупреждает о такой ситуации заранее.

Про `config:cache` — не запускать, как и договаривались раньше.

`magnoolia:seed-lists` идемпотентна: список, в котором уже есть строки, не трогается.
Повторный запуск не создаёт дублей в медиатеке. Чтобы перезалить конкретный список:
`php artisan magnoolia:seed-lists --list=kkk.faq --force`.

После сида ничего не опубликовано — сайт работает как раньше. Индрек открывает
**Nimekirjad**, правит, затем **Publish Website Changes**.
