# MAGNOOLIA PHASE 36 — план: чтобы Индрек всё менял сам

Черновик на согласование. Основан не на догадках, а на 20+ правках, которые мы физически сделали в Phase 35.1 — по каждой известно, где лежит контент и почему клиент не смог изменить его сам.

---

## 1. Что показала Phase 35.1

Из 21 пункта Индрека **сегодня в админке правятся 4**. Остальные 17 потребовали разработчика.

Но важнее не цифра, а **закономерность**. Все правки легли ровно в три корзины:

| Корзина | Доля | Где лежит сейчас | Пример из списка Индрека |
|---|---|---|---|
| **Тексты** | ~60% | `lang/{et,ru,en}/magnoolia.php` | «Netopind» → «Netopind kokku», подписи модалки, факты планов, FAQ |
| **Картинки** | ~25% | путь к файлу прямо в коде | фото на главной, рендеры Arhitektuur, чёрные листы Sisedisain, шапки подстраниц |
| **Списки** | ~15% | PHP-массивы в lang или конфиге | 12 карточек на главной, 4 элемента Arhitektuur, lisateenused, проекты застройщика, порядок галереи |

**Вывод: не нужно 13 отдельных редакторов.** Нужно три механизма, по одному на корзину. Идея с модулем Lists — верная, она закрывает третью корзину. Плюс к ней нужны ещё две.

### Почему это не косметика

Ошибка «143,2 м²» прожила на сайте месяцами в трёх языках и в структурированных данных Google. Не потому что её не заметили — а потому что **исправить её было некому без разработчика**. Это и есть настоящая цена нередактируемости.

## 3. Предлагаемые модули

### Модуль A — «Тексты страниц» (расширение Content-редактора)

**Проблема.** Сегодня редактируются только заголовок и вводный абзац страницы. Всё под ними — факты, подписи, FAQ — в lang-файлах.

**Решение.** Снять ограничение белого списка из 34 ключей. Любой ключ `magnoolia.*` можно зарегистрировать как редактируемый и сгруппировать по странице и блоку.

Ключевое — **человеческие подписи вместо технических ключей**:

```
Страница «Kodud ja hinnad»
  └ Таблица домов
      ├ Заголовок колонки площади        [Netopind kokku]
      └ Заголовок колонки участка        [Isiklik maa-ala]
  └ Карточки планов
      ├ Бейдж варианта A                 [Variant A — rohkem vannitubasid]
      └ Заголовок варианта A             [4-toaline kodu — keskmine boks]
```

Три языка рядом в одной строке. Проходит через существующий поток preview → publish, значит есть откат.

**Закрывает:** 2, 11, 12, 14 (текст), 20 (текст), подписи модалок — включая вопрос «Kuidas seda teksti muuta?» со скриншота.

---

### Модуль B — «Картинки блоков» (медиа-слоты)

**Проблема.** Каждая картинка задана в коде именем файла. Замена = задача разработчику, даже если это просто другой рендер.

**Решение.** Именованные слоты. Слот — это место на сайте («Главная → блок Tutvustus → фото»), к которому привязывается запись медиатеки. В коде остаётся `mg_slot('home.intro.image')` с текущим файлом как запасным вариантом — если слот пуст, сайт работает как сейчас.

Обязательно: alt-текст на трёх языках прямо в слоте (сегодня alt тоже в коде), автогенерация webp-вариантов при загрузке — тот же пайплайн, что мы гоняли руками.

**Закрывает:** 3, 4 (картинки), 7, 13, 19, 21.

---

### Модуль C — «Списки» (ваша идея, с типом списка)

**Проблема.** Самая болезненная корзина. Карточки на главной — массив из 12 элементов в lang-файле. Элементы Arhitektuur — 4 элемента. Lisateenused, проекты застройщика, категории Sisedisain, порядок галереи — то же самое.

**Решение.** Один модуль «Списки», каждый список имеет **тип**, тип задаёт набор полей:

| Тип списка | Поля элемента | Где на сайте |
|---|---|---|
| `feature_cards` | картинка, заголовок, 3 подписи | 12 карточек на главной |
| `exterior_elements` | картинка, надзаголовок, заголовок, текст, список пунктов | 4 элемента Arhitektuur |
| `spec_items` | название, бейдж (Standard / Lisatasu eest) | позиции Sisedisain |
| `projects` | картинка, название, ссылка | проекты застройщика |
| `gallery` | картинка, alt, категория, **порядок** | галерея |
| `faq` | вопрос, ответ | KKK + FAQ-схема |

Общее для всех: добавить / удалить / **перетащить порядок**, три языка, preview → publish.

Важная деталь: FAQ-список должен **автоматически обновлять JSON-LD**. Сегодня видимый FAQ и структурированные данные для Google — два разных места, и они уже разъезжались (мы это чинили в пункте 12).

**Закрывает:** 4 (заголовки), 8, 10, 12 (FAQ), 14, 20.

## 4. Сквозная вещь, без которой остальное не работает

**«Где этот текст на странице?»**

Даже с открытым Translation Manager клиент не найдёт нужную строку: ключей больше тысячи, а называются они `magnoolia.rowhouse.yard_inline`.

Предлагаю режим **«Правка на странице»**: в предпросмотре у каждого редактируемого блока появляется карандаш, клик ведёт прямо в нужное поле редактора. Обратный путь тоже: в редакторе ссылка «показать на сайте».

Это превращает «найди ключ в списке из тысячи» в «ткни в то, что видишь». Без этого модули A и C останутся теорией.

## 7. Решения приняты (2026-08-24)

| # | Вопрос | Решение | Что это значит технически |
|---|---|---|---|
| 1 | Роли | **Открыть Translation Manager клиенту сразу** | Роли в системе: `magnoolia_admin`, `magnoolia_client_admin`, `magnoolia_editor`. Сейчас страница требует `magnoolia_admin`. Добавляем `magnoolia_client_admin`. Правка идёт напрямую в lang-файлы, но со снапшотами и откатом — они уже реализованы |
| 2 | Публикация картинок | **Через publish** | Слоты хранят ссылку на медиа-запись в черновике; на сайт попадают только после «Publish Website Changes». Значит и откат через Publications работает для картинок так же, как для текстов |
| 3 | Глубина списков | **Все 6 типов** | `feature_cards`, `exterior_elements`, `spec_items`, `projects`, `gallery`, `faq` |
| 4 | Языки | **Не обязательны, пустые языки показывают эстонский** | См. ниже — тут есть подвох |

### Подвох в решении 4

Сегодня `mg_text()` при пустом переопределении откатывается **не на эстонский, а на lang-файл текущего языка**:

```php
$override = $payload['content'][$locale][$key] ?? null;
if (is_string($override) && $override !== '') return $override;
return $default ?? (string) __('magnoolia.' . $key);   // ← RU lang-файл, не ET
```

То есть если клиент поправит эстонский и оставит русский пустым, на русской странице останется **старый русский текст из lang-файла** — он будет противоречить свежему эстонскому. Ровно это уже произошло с заголовком «Ridaelamu mugavus, eramaja kogemus»: в ET поправлен, в RU по-прежнему про приватность.

Правильная цепочка под решение 4:

1. переопределение для текущего языка — если не пустое;
2. **иначе переопределение для ET** — если оно есть (значит текст правили, и эстонский свежее старого перевода);
3. иначе lang-файл текущего языка (для ключей, которые никто не трогал — там перевод корректный).

Ключевой шаг именно второй: **свежая эстонская правка должна вытеснять устаревший перевод**, иначе «необязательные языки» превращаются в тихие расхождения.

## 8. Честное замечание про объём

Это не «доделать админку», а полноценный CMS-слой поверх существующего сайта. По ощущению — самый большой этап проекта после самого сайта.

Альтернатива дешевле: оставить как есть и правки делать через разработчика. Она работает ровно до следующего «143,2 м²» — ошибки в цене или площади, которую никто не может убрать сам, пока разработчик занят.

Между этими крайностями есть середина: **Этапы 1–2**. Они дают контроль над текстами (60% всех правок сегодня) за долю усилий. Картинки и списки можно отложить, если бюджет ограничен.
